# arch-case-collector

建筑设计案例搜集 Skill：把一个主题转化为可核验、可回源、可人工确认的案例候选与快速收录材料。它覆盖来源检索、两道闸门筛选、图片本地化、证据整理、案例排名、来源溯源，以及 Phase 5 的增量研究规划。

## 目标与基本原则

- 来源优先级：事务所/官方（S）> 专业建筑媒体（A）> 中文一手社区媒体（B）> 百科与索引（C）。
- 不把转载数量当成独立证据：通过来源域名、内容哈希和来源类型识别转载关系。
- 事实字段必须回源；来源冲突要显式记录，不能静默择一或臆造。
- 图片分类必须逐张视觉核验，不能根据文章标题、栏目名或文件名推断。
- 默认先生成候选清单，人工确认后才进入正式归档；自动化只提出建议，不代替证据裁决。

### 产业独栋专项门槛

产业独栋、独栋厂房、研发办公独栋等主题，正式收录必须有**该独栋自身可核验的平面图**。没有清晰平面图的项目只能作为候选或研究线索，不进入正式案例库。

总平面、园区规划图、产品分布轴测图、沙盘图、效果图和营销海报可以作为补充素材，但不能替代独栋平面图。图纸来源通常优先检查园区/开发商公众号正文、招商门户和产品介绍类资料；产业门户的“户型图”栏目必须逐张复核。

## 总体架构

```text
用户主题 / brief
        |
        v
配置与来源策略 ──> 发现轮检索 ──> 核验轮回源
                                      |
                                      v
                          图片下载 + 逐张视觉核验
                                      |
                                      v
                    两道闸门：相关性/证据 + 素材/平面图
                                      |
                                      v
                 候选清单 ──人工确认──> 快速收录笔记与回执
                                      |
                                      v
             Phase 4 排名/缺口/溯源 ──> Phase 5 主动研究循环
```

主要组件：

| 路径 | 职责 |
| --- | --- |
| `SKILL.md` | 操作规范、来源分级、筛选门槛、归档边界与安全红线 |
| `config.yaml` | vault、暂存区、来源、评分阈值和默认选项 |
| `core/research_loop.py` | 读取 Phase 4 结果，计算研究缺口、优先级、查询和预算 |
| `pipeline/active_research.py` | Phase 5 命令行入口 |
| `pipeline/render_dashboard.py` | 生成研究缺口 Dashboard |
| `schemas/` | 机器可校验的输出结构，目前包含研究优先级 schema |
| `scripts/` | 图片抓取、审图板、归档、vault 验收等复用脚本 |
| `examples/` | 可运行的 Phase 4/5 示例批次 |
| `tests/` | Phase 5 规划、预算、Dashboard 和溯源回退测试 |

## 工作流程

### 1. 解析主题与配置

读取 `config.yaml`，确定主题、数量、地域、年份、来源语言、评分模式、是否需要浏览器和是否启用人工确认。执行真实 vault 任务前，必须先读取 vault 的案例库规范；本仓库本身不替代 vault 规范。

### 2. 发现轮与核验轮

先用主题词、类型词和特征词发现候选，再返回更高等级来源核验建筑师、地点、年份、面积、业主和图纸。登录墙或 JS 来源按来源配置走浏览器通道；无登录墙来源可用直接抓取或搜索工具。

### 3. 两道闸门

第一道闸门检查类型、地域、时间、来源可信度、相关性和事实证据；第二道闸门检查图片、图纸、字段完整度和素材质量。任一硬条件不满足，项目进入候选或淘汰，不直接进入正式收录。

素材统计必须标记“已逐张视觉核验”。户型/平面图、总平面/鸟瞰、效果图和海报分开计数；海报中的微缩平面、打码图和无法读图的缩略图不能计作可用平面图。

### 4. 候选确认与归档

候选清单展示项目、来源级别、评分、素材计数、缺口和查重结果。用户确认后，才生成快速收录笔记、图片引用和搜集回执。归档采用只增不改原则，并执行：暂存 → 自检 → 原子写入 → 读回验收。

### 5. Phase 4 与 Phase 5

Phase 4 负责排名、相似案例、来源溯源和覆盖 Dashboard；Phase 5 根据这些结果决定下一轮最值得研究的缺口，而不是重新完整搜索。

Phase 5 识别五类缺口：

1. 高相关但证据弱；
2. 缺关键图纸；
3. 只有转载来源；
4. 字段冲突未解决；
5. 与目标高度相似但资料不完整。

运行：

```bash
python pipeline/active_research.py batches/<id> \
  --max-queries 40 \
  --max-fetches 24 \
  --max-review-minutes 180

python pipeline/render_dashboard.py batches/<id>
```

输入可以包括：`rankings.jsonl`、`gaps.jsonl`、`sources.jsonl`、`assets.jsonl`、`provenance_graph.json` 和 `similarity.jsonl`。可选输入缺失时按空集处理，便于对部分完成的批次制定下一轮计划。

输出：

- `research_priorities.jsonl`：每个案例/缺口的一条解释性研究建议；
- `queries.jsonl`：按缺口生成的增量查询，不重复跑完整搜索；
- `research_budget.json`：查询、抓取、人工审阅预算及停止条件；
- `review/dashboard.html`：前 10 个最值得研究的缺口、预算和停止条件。

## 人工确认边界与停止条件

Phase 5 的所有建议都保留以下状态：

```json
{
  "requires_human_review": true,
  "auto_apply": false,
  "status": "proposed"
}
```

查询默认 `approved: false`。Phase 5 不会自动写入案例事实、解决字段冲突、裁决证据、确认图片类型或修改 `cases.jsonl`。出现以下任一情况即停止该缺口：

- 人工确认缺口已经解决；
- 连续两条定向查询没有带来新的来源、证据或素材；
- 查询、抓取或人工审阅预算耗尽。

## 当前局限性

- 公开资料不稳定：登录墙、反爬、403、429、懒加载和地区网络会导致来源或图片无法覆盖；系统会记录未覆盖原因，不用低质量来源硬补。
- 图片语义仍需人工目视核验。模型或文件名不能可靠区分平面图、总平面、海报和效果图。
- 产业独栋公开资料经常有面积、层高、荷载和柱距，但缺少独栋平面图；因此严格门槛会让部分项目停留在候选状态。
- 内容哈希可以识别完全相同或近似转载，但无法保证识别所有改写、裁切、换水印和二次编辑。
- 来源评分、相似度和收益估计是可解释的离线启发式，不是事实可信度的自动证明。
- 当前测试使用固定 fixture，覆盖规划逻辑和输出结构，不等价于对实时网站、登录态和下载链路的在线回归测试。
- `config.yaml` 默认包含本机 Windows vault/暂存路径；迁移到其他机器前必须修改路径并检查 vault 规范。
- 本项目输出的是快速收录与研究计划，不自动完成深度归档、版权授权判断或最终建筑专业审查。

## 开发与回归检查

在仓库根目录执行：

```bash
python -m unittest discover -s tests -v
python -m compileall -q core pipeline scripts
```

新增或修改输出结构时，应同步更新 schema、示例批次和测试。提交前还应检查：

- `git diff --check` 无空白错误；
- 未提交凭据、token 或个人路径之外的敏感信息；
- Phase 5 输出仍然保留人工确认状态；
- Dashboard 能显示“下一步最值得研究的缺口”和停止条件。

## 许可证与使用边界

本仓库用于个人建筑研究与案例整理。抓取和保存图片时应遵守来源网站条款、版权和访问频率限制；遇到登录失效、验证码或明确禁止自动化的页面，应交还人工处理。
